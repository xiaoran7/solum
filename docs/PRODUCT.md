# Product

## Register

product

## Platform

mobile (Android first; iOS/HarmonyOS later)

（产品只做移动端。Android 是当前主开发、首发和验收平台；项目成熟后补齐 iOS 与 HarmonyOS。没有网页产品，也不再发布桌面客户端。三端可以使用不同平台壳层，但必须共享产品语义、服务端契约和跨平台备份格式。）

## Users

应用面向使用 Android、iOS 或 HarmonyOS 手机的个人用户，当前优先服务 Android。手机是唯一业务权威，也是通知、健康、分享、相机/语音等生活信息源的汇聚点；统一中心允许多个账号共用账号、AI 与加密备份服务，但每个会话和备份只属于一个账号。换手机通过端到端加密快照恢复，可跨操作系统接管，不把旧手机和新手机设计成长期并发写入的两个客户端。语言：简体中文。

## Access Model

Solum 先在 Android 交付可信的移动本地工作台，再通过同一账号与协议补齐 iOS/HarmonyOS；账号解锁云端 AI、加密备份和换机恢复。第一次完成隐私同意后必须明确选择「注册」「登录」或「访客使用」，不能把注册入口藏在设置里。

- **访客**：今天的本地记录、基础日程与提醒、本地记忆台账、行为记录和仅限本机数据的搜索。内容留在 guest profile，可持续使用，不是只能观看的演示模式。
- **完整账号**：在访客能力上增加云端对话与推理、主动建议、复盘、穿戴、通知智能、邮箱、资料、组件、端到端加密备份、换机恢复、福利告警和完整连接设置。登录后即由 Solum Center 提供一个可直接调用的默认模型，不要求用户先购买或填写第三方 API Key。
- **执行边界**：受限能力既要在界面中显示锁定状态，也必须由 Rust 壳层阻止访客启用。旧版直连 API Key、旧同步 token、桌面入口或遗留配置不得绕过账号会话。
- **身份切换**：登录或注册成功后进入该账号的隔离 profile；退出后回到 guest profile。切换通过整进程重启关闭旧数据库连接、后台任务和内存上下文。

账号是完整能力和未来订阅的身份基础，不等于已经付费。中心会返回当前权益名称、月度请求额度、已用/剩余量和重置时间，为以后接支付系统建立服务端权威账本；当前版本仍不展示虚构价格，也不声称支付已经接通。

模型选择是订阅能力的一部分，但不是任意代理配置：用户从中心允许的模型目录中选择，默认模型始终保留。所选模型调用失败且回复尚未开始时，中心自动改用默认模型；界面必须明确显示本次请求原本选择什么、实际使用什么、是否回退以及回退原因。额度由中心在请求发出前原子扣减，客户端只显示中心返回的统计，不以本地计数决定是否还能调用。

## Product Purpose

Solum 是一个"真正了解你"的个性化私人 agent：自然语言排日程、分级提前提醒、主动习惯问询、行为日志、周报复盘、数字人格养成、穿戴数据感知，并以用户主动连接的邮箱承接工作与生活通信。成功的样子：用户信任它交付的每一条提醒（可靠性是信任基础），并且敢把生活数据交给它（因为数据默认只在本地、外流边界由用户自己掌控，记忆完全可见可删）。

## Positioning

一个隐私边界归你掌控、越用越懂你的私人管家——不是带聊天框的工具箱，也不是把你的生活打包上传给厂商的助手。

已发布版本的数据边界以 [PRIVACY.md](PRIVACY.md) 为准。2026-08-22 的目标变化是：全部可移植用户数据（包括完整对话、人格、审计、健康、通知结果、资料和允许迁移的账户配置/凭据）可以作为**端到端加密备份密文**离开手机，但这绝不等于允许它们作为 AI 明文上下文。备份功能发布前必须同步更新隐私政策、迁移旧选择并重新取得用户确认；在此之前不得用目标设计覆盖当前版本的真实承诺。日常 AI 上行继续只使用当前操作所需的最小上下文；通知上云仍默认关闭，邮件正文仍不进入 LLM、recall 或记忆。

## Brand Personality

安静、可靠、有分寸（quiet, dependable, discreet）。像一本留白充分、索引清楚的私人档案：平时安静承载，需要时用一个微小信号点提示你。主动但不聒噪；亲近但不越界；确认高危操作时严肃分明。

## Anti-references

- 通用 SaaS 仪表盘脸（靛紫/蓝渐变、脱离真实任务的 KPI 卡片与 hero 大数字）。
- "AI 产品"刻板印象（紫色荧光、渐变文字、玻璃拟态堆砌）。
- 聊天玩具感（花哨气泡、贴纸、emoji 图标当 UI）。
- 米黄纸张底色的"温暖手账风"——温度由文字节奏、圆角轮廓与微粉信号承担，底色保持纯净中性。

## Design Principles

1. **四个根入口，不是功能清单**：今天 / 记忆 / 计划 / 搜索是长期稳定的用户心智；账户身份是应用外壳的一部分，低频配置和连接器进入工具层，不能因新增能力继续扩张底栏。
2. **信号点出现即有事**：微粉色 = "这里有新状态/需要留意"（在线、待处理、选中提示），只占极小面积；主动作使用高对比黑白，不把信号色铺成大色块。
3. **可靠感来自克制**：中性底色、系统字体、180–520ms 的分层状态动效；熟悉的控件词汇（earned familiarity），不为花哨发明交互。长时动效只用于品牌在线信号，页面编排必须短、可中断且尊重 reduced-motion。
4. **危险要有重量**：高危确认流程在视觉上与日常操作截然分开（红色、模态、后果预览），呼应架构级 HITL 护栏。
5. **记忆必须透明**：台账/审计等数据视图允许高密度呈现，让"agent 记住了什么"一目了然、可删可查。
6. **搜索回到原上下文**：统一搜索只索引本机已经加载的计划、记忆与行为数据；结果不是新的信息孤岛，点击必须回到所属视图继续处理。
7. **锁定也要可理解**：访客能看到完整产品的能力地图，但受限入口必须同时说明价值和解锁动作；不能静默隐藏，也不能让用户进入半失效表单后才发现不可用。

## Accessibility & Inclusion

- 文本对比 ≥ 4.5:1（正文）/ 3:1（大字与图形），深浅两套主题分别校验。
- 全键盘可达：focus-visible 焦点环；模态可 Esc 关闭。
- `prefers-reduced-motion` 下全部动效退化为即时切换。
- 触控目标 ≥ 44px（移动端底部导航、操作按钮）。
- 不禁用缩放。
