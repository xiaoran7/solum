# Solum 持久踩坑

## 构建与仓库

- 脚本化的批量改写必须**回读校验**，不能只报“处理了 N 处”。两次真实翻车：正则用 `` `pub(super) $1$2 ` `` 之类的占位丢了捕获组，把 `fn cursor(...)` 改成 `fn (...)`；匹配 `^(\s*)(const|fn|...) .*\bNAME\b` 又会先撞上**调用点**而不是定义处，于是“已处理 6/6”实际一个都没改。凡是脚本改源码，跑完立刻按行号回读比对，并对没命中的名字**报错**而非跳过。
- 脚本的工作目录会漂。改文件前先 `pwd` 确认，或一律用相对仓库根的路径；一次在仓库根而非目标目录的运行，会把四个 `.rs` 副本落在仓库根上，看着像源码，实则是半成品。
- 拆文件时，跨文件可见性不能靠 `use super::*;` 的 glob 转出：`pub(super)` 在子模块里已经等于“父模块可见”，`mod.rs` 再以 `pub(super) use` 转出属于放大，会 E0364；要转出必须把声明提到 `pub(crate)`。反过来，`pub use crypto::*;` 若该模块无 `pub` 项则是空转，clippy 会报 glob import 没有可 reexport 的可见项。
- 文件内 `#[cfg(test)] mod tests` 的外壳归 `mod.rs`，测试体落到 `tests.rs` 时要去一层缩进，并**按花括号配平复核**——嵌套多一层/少一层编译器未必立刻报错，但 `use super::*` 的解析层级已经变了。
- `git add` 一个已被重命名（`RM`）的文件会报 pathspec 不存在；用 `git status --short` 看清索引状态再分批 `add` 具体路径。
- 不搬运 `target/`：Cargo/Tauri 产物含绝对路径和旧权限元数据；迁移工作区后先干净重建。
- Windows 不用 `>` 生成 SQLite/二进制或多行源码；避免产生 `nul`。临时文件放项目内忽略的 `_scratch/`。
- Android 交叉编译保持 rustls/纯 Rust 依赖，新增 crate 前检查 native C/OpenSSL 链。
- Android 与 HarmonyOS 是独立 Git 仓，不能从父目录操作或跨仓一次提交。

## 数据与同步

- Core 时间必须注入；测试读取系统时钟会造成不可复现的提醒/合并错误。
- SQLite schema、同步表白名单、触发器、apply 分支和固定夹具必须一起演进；少一处会形成静默 history gap。
- JSON 解析失败是错误，不等于“未知表隔离”；隔离只处理被明确识别为可泊车的未来数据。
- 状态文件和导入使用临时文件 + flush + rename；恢复只写入经过完整预检的空目标。
- `local_only` 是数据分类，不是 UI 标签；任何 recall/LLM 路径都必须在数据层过滤。
- 纯移动式拆分的等价性证据要**按分节**给，不是整文件比一次：整文件 diff 会被 rustfmt 对变长签名的换行淹没，看起来像有实质差异。逐分节比 token 流（标识符/字符串/字符/裸串 + 逐字符标点），并显式列出“允许的改动”（可见性放开、rustfmt 补的行尾逗号），剩下的必须完全一致。
- 找“分节起点”不能只搜 `// ---- `：末尾的 `#[cfg(test)]` 块常常没有横幅，按“首个横幅”切片会**整段丢掉测试套件**而脚本仍报成功。行范围要显式声明。
- 等价性脚本“还原可见性”时要还原**到拆分前的实际值**，不能一律删掉 `pub(...)`。测试夹具常是拆分前就写好的 `pub(crate)`（在单模块里用不到那么宽），拆到兄弟模块后降为 `pub(super)`；脚本只删不加就会把拆分前就有的 `pub(crate)` 一并抹掉，报出假的差异。让脚本按 `名字:拆分前可见性` 显式声明。
- 等价性脚本本身要做**反向验证**：造一个含多余语句、含改动过的函数名的副本当对照，确认脚本报错。写完脚本先证明它会咬人，再拿它判真伪。反过来，故意只删一行 `use` 时脚本不报——那是设计上允许的差异，不该算失配。半路发现对照没生效时，先确认变异是否真的落地，再怀疑脚本。
- `mod.rs` 那一段不能靠 token 比对下结论：条目都搬进了分节，模块文件只剩文档头和归位过来的 `use`，逐 token 比对是空转（还会报"零 token"）。改为断言原文件的 `use` 行逐字存在且顺序不变——兄弟分节靠 `use super::*;` 看到它们，丢一条或调顺序会静默改变每个分节的可见名字。宁可显式说"此处无可比对项"，也不要输出一行看起来像通过的 OK。

## Android/设备

- “权限已授予”不等于后台能力工作；receiver/service 必须出现在 Release manifest，并验证锁屏、进程回收与重启。
- `force-stop` 会让 Android 主动阻断 alarm/receiver，不能用于正常后台恢复验收。
- 浏览器健康接口成功不证明应用 rustls 可达；按 DNS、SNI、ClientHello、代理和设备网络逐层探测。
- `offsetParent === null` 对 fixed/sticky 元素不代表不可见；用 computed style、视口矩形和必要的截图判断。
- DOM 属性/类名正确不等于渲染正确；mock-IPC 后仍需真实浏览器/设备走查。
- WebView 瞬态界面必须统一登记到同一个栈顶 history 条目；漏掉一种弹窗/面板会让 Android 返回键在浮层仍可见时误切底层视图。程序关闭浮层后的异步 `popstate` 也要吞掉，不能再触发一次视图回退。
- 响应式覆盖必须声明在对应桌面基础规则之后；账号门曾因桌面双列规则后声明，在 390px 下把说明栏压成单字竖排并覆盖表单。真实 320/390/1000px 渲染是发布门槛，不能只看选择器存在。
- 不要在启动或一次对话写入后刷新所有隐藏页面；台账单次刷新会并发读取多个数据层。隐藏视图进入时再刷新，高频刷新要 single-flight，页面隐藏时暂停周期任务。
- 渲染函数内向 `document` 注册监听器必须可解绑；组件详情菜单曾在每次进入时累积外部点击监听，造成越用越慢和重复回调。
- `account_status_get.logged_in=true` 不代表会话仍可用；刷新 token 失败会写入 `state_error`。只渲染错误文案会把用户困在伪登录态，必须与普通 IPC 的 401/过期错误一起进入统一退出与登录重定向。
- 不把相册原图直接塞进 `localStorage`：高像素照片会迅速撞上 WebView 配额并放大解码内存。先限制输入体积、居中裁切、压缩并再次检查编码后大小；解码失败或超限时保留原头像。

## 服务端

- Schema 开头 `revoke all on schema public from public` 会连 pgcrypto 的 `digest()` 一起锁死，运行时角色解析不到扩展函数并报 `function ... does not exist`；库内哈希用 pg_catalog 内置 `sha256()`，不要依赖 public schema 的扩展函数。
- 窗口函数先于 `LIMIT` 执行：把 `octet_length(ciphertext)` 累计窗口和密文选择写进同一层查询，`since` 之后的整段历史都会被解包。pull 必须先在有界候选集上算尺寸，再对入选行取密文。
- 集成测试不自行初始化角色/schema，需按 compose migrate 同款流程预置全新测试库；断言含全局 identity 序列号（如 42/74），复用跑过的库会假失败。
- 无本地 Postgres/Docker 时，可在 VPS 起 `--rm` Postgres 容器（仅绑 127.0.0.1）+ SSH 隧道跑集成测试，用后即删。
- **服务端 LLM Upstream 容器网络与 CPA Guard 连通**：
  - 客户端不直连供应商或 CPA，而是经由 Solum Center（`solum-cloud` 容器）代理；
  - 客户端更新默认模型（如从 `qwen3.5-2b` 迁移到 `gemini-3.8-flash-high`）时，**必须同步检查并更新 VPS 生产环境的 `.env` 配置**（`SOLUM_DEFAULT_MODEL`、`SOLUM_ALLOWED_MODELS`、`SOLUM_LLM_BASE_URL`、`SOLUM_LLM_API_KEY`）并重启容器，否则客户端登录后请求 Center 会直接报 502 upstream unavailable 或模型不在目录；
  - 容器不能通过自身回环访问宿主服务；核对实际 Docker 网络、网关可达的监听地址和防火墙。不要把历史网桥 IP 或 `0.0.0.0` 当作所有部署的固定要求。

## 安全

- Guard token 一次性且绑定动作/参数/主体；模型或页面不能自行构造。
- 不把生产 token、通知正文、健康数据、设备账号或签名材料写入日志/文档/测试夹具。
- 主机 API、模拟器、Debug 和真机 Release 结论各自独立，报告必须写清证据层级。
- 登录成功即重启应用（Android 重启 Activity、桌面重启进程），登录命令的返回值到不了任何 UI；必须跨重启呈现的一次性内容（如首登签发的恢复码）要先原子落盘到账号 profile 目录，由下次启动读取并强提醒、确认后才删除。签发信封成功但展示链路中断，等于把 E2EE 唯一钥匙静默丢弃，且设置页状态会给出「已设置」的假安心。
