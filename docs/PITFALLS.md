# Solum 持久踩坑

## 构建与仓库

- 脚本化的批量改写必须**回读校验**，不能只报“处理了 N 处”。两次真实翻车：正则用 `` `pub(super) $1$2 ` `` 之类的占位丢了捕获组，把 `fn cursor(...)` 改成 `fn (...)`；匹配 `^(\s*)(const|fn|...) .*\bNAME\b` 又会先撞上**调用点**而不是定义处，于是“已处理 6/6”实际一个都没改。凡是脚本改源码，跑完立刻按行号回读比对，并对没命中的名字**报错**而非跳过。
- 脚本的工作目录会漂。改文件前先 `pwd` 确认，或一律用相对仓库根的路径；一次在仓库根而非目标目录的运行，会把四个 `.rs` 副本落在仓库根上，看着像源码，实则是半成品。
- 拆文件时，跨文件可见性不能靠 `use super::*;` 的 glob 转出：`pub(super)` 在子模块里已经等于“父模块可见”，`mod.rs` 再以 `pub(super) use` 转出属于放大，会 E0364；要转出必须把声明提到 `pub(crate)`。反过来，`pub use crypto::*;` 若该模块无 `pub` 项则是空转，clippy 会报 glob import 没有可 reexport 的可见项。
- 文件内 `#[cfg(test)] mod tests` 的外壳归 `mod.rs`，测试体落到 `tests.rs` 时要去一层缩进，并**按花括号配平复核**——嵌套多一层/少一层编译器未必立刻报错，但 `use super::*` 的解析层级已经变了。
- `git add` 一个已被重命名（`RM`）的文件会报 pathspec 不存在；用 `git status --short` 看清索引状态再分批 `add` 具体路径。
- 不搬运 `target/`：Cargo/Tauri 产物含绝对路径和旧权限元数据；迁移工作区后先干净重建。
- Windows 不用 `>` 生成 SQLite/二进制或多行源码；避免产生 `nul`。临时文件放项目内忽略的 `_scratch/`。
- Android 交叉编译保持 rustls/纯 Rust 依赖，新增 crate 前检查 native C/OpenSSL 链。
- Android 与 HarmonyOS 是独立 Git 仓，不能从父目录操作或跨仓一次提交。
- 拆分的等价性校验要**按分节比对 token 流**，不是只比“拼回原文件逐字节一致”。逐字节一致证明不了切在对的位置：一个函数被切成两半，拼回去仍然逐字节相同。边界守卫应断言**新分节的第一条非空行是顶层项**（`#[`、文档注释，或顶格的 `const`/`struct`/`fn`/`impl` 等）；用“上一分节的最后一行”当判据无效——被切断项的尾巴通常就是顶格的 `}` 或 `;`，和干净的结尾长得一样。
- **重复的 `mod X;` 不是 cosmetic**。同一个模块声明两次，编译器报 E0428 看着无害，但它会拿到两个 DefId，于是所有经由该模块到达的类型不再与自身匹配：原本正确的代码会报 E0308 “expected `email::config::EmailProvider`, found a different `email::config::EmailProvider`”。拆分的装配步骤必须**可重入**，写入前按自身标记先擦除（文档头、`mod` 声明块、re-export 块各自带标记），且空行折叠放在该步**最后**——头部是前缀重写、`mod` 块在其后插入，折叠跑得太早看不到它们留下的空行，每跑一次就多一行。
- **`mod <name>;` 会遮蔽同名外部 crate**。模块内 `mod imap;` 声明后，模块作用域里的 `imap::Session` 指向分节而非 `imap` crate，于是 `use super::*;` 引进来的 crate 路径集体失效，报出一串看似“某分节没声明 Session”的错误。分节名与依赖 crate 同名时直接改名（`imap` → `mail`），比在文件里撒 `::imap::` 前缀干净。
- **跨分节 `use` 行必须由编译器驱动**。`use super::*;` 已经把父模块的 `pub use` 一起带进来，再显式导入同名项就是 E0252；漏写则是 E0425/E0422。两种错都很便宜地犯、又很难发现，所以别手抄：跑 `cargo check` 读未解析名字、按分节归属生成导入、循环到没有为止。
- **E0616 在本工具链上会变成 E0451 复数形式**（`fields \`a\`, \`b\` and \`c\` of struct \`S\` are private`）。用单个 `` `[^`]*` `` 跨不过这个逗号加 and 的列表，要 `` `[^`]+` `` 加惰性 `.*?`。`fields?` 的回溯猜测是错的——`probe` 证明 `fields?` 从来没匹配上任何东西。
- **等价性校验的“撤销加宽”要按原样恢复拼写**。拆分把 `pub` 加宽成 `pub(super)`，校验时撤销必须放回 `pub ` 而不是 `pub(crate) `：分词把限定形式的括号和标识符算作额外 token，恢复错了会报出一个“少一个 token”的假差异。`WIDENED` 条目要能区分裸 `pub`（单 token）与 `pub(crate)`/`pub(super)`。撤销正则的关键字组**必须包含 `type`**——`pub(super) type X = ...` 别名否则完全不撤销，差异出现在 token 0，读起来像丢了一整行。方法同理：E0624 只说是私有**方法**，调用方要的是**类型**在作用域里，这个组合编译器不会告诉你。
- 拆分的等价性校验还要**忽略拆分新增的 `use super::<section>::{...};`**。这些导入是拆分必须加的（名字原本是同级的，现在多了一层），不属于“代码”差异；早先只对 `tests` 段做这件事，换一个文件就立刻报出两段假差异。规则要放在 `tests` 分支**之后**——那个分支会重新赋值 `got`/`want0`，放在前面看着对、实际什么都没做。
- **装配脚本必须可重入，且校验要数次数**。`mod` 声明写“匹配到即可”时，重复的 `mod X;` 能通过校验——E0428 看着无害，但它让模块拿到两个 DefId，编译器会在完全正确的代码上报 E0308“同名但不同的类型”。文档头同理，要按**原文出现次数**校验，而不是数 `//!` 行数：拆分器自己写在文件头的面包屑也是 `//!`，按行数查会把一次干净的运行判成重复。空行折叠必须放在该步**最后**。
- **跨分节共用的私有常量要留在父模块**。切分时它们容易跟着某个分节走，于是兄弟分节引用时报 E0603。常量属于父模块的公共词汇表——兄弟正是通过 `use super::*;` 拿到它们的——所以 `mod` 一节的行区间要包含整段常量。
- **re-export 的可见性要跟着被转出项走**。拆分前是 `pub(crate)` 的项，`pub use` 转出即 E0364。装配脚本的 re-export 条目要能自带可见性并校验条目形状，别把这条留给编译期。
- 单边界切分**表达不了"按职责归类"**。有的文件把一个校验器夹在两个构造器之间（`export_v3.rs` 的 `validate_portable_document`），此时"构造器归一节、校验器归另一节"只能二选一：要么接受一节里混两种职责，要么把区间切成非连续——后者是错的，因为拼回原文件会破坏"逐字节可重组"这条等价性证据。正确做法是承认物理顺序的限制，在分节说明里写清取舍。
- re-export 块若锚在"第一个 const/type 之前"，当 `mod` 一节自己没有任何条目时就没有锚点（本次所有常量都在别处）。退化为锚在最后一条 import 之后即可——但**首行就是那一条 import 时**用 `lastIndexOf("\nuse ")` 找不到（首行前面没有换行），要单独处理首行这种情况。
- 写批处理脚本时，**没有上界的循环比报错更糟**。跳过文件头部的循环走到末尾后取行恒为 `""`，而 `""` 匹配空行判断，越界后永远前进一格——脚本静默挂住，报不出任何线索。所有走文件的循环都要按长度收敛。
- **"某条目都还在"这类检查不能用集合，要用多重集**。`#[cfg(...)]` 成对的实现是同一文件里两次同名声明（每个平台一份），不是重复；按集合判会报成接线 bug。正确做法是**按拆分前的声明次数核对**：少了是丢失，多了才是重复。
- **脚本的正则要覆盖目标文件里出现的全部形态**。`async fn` / `unsafe fn` 把修饰符放在可见性与关键字之间，只认 `pub fn` 的模式对每个 `async fn` 都匹配不到，报出来的却是"找不到该声明"——而函数就在文件里。同理，跨 crate 的引用有 `mod::Name` 与 `crate::mod::Name`/`solum_core::mod::Name` 两种写法，只写一种会静默返回空列表，看起来像"没人用这个模块"。写这类脚本先拿一个已知有目标的文件验一遍，别把空结果当事实。
- **工具的默认值要慎用**。`widen-fields.mjs` 的包名默认 `solum-core`，在 `solum-app` 上调用时它检查了**错误的 crate**，发现那个 crate 没问题，于是自信地打印"clean after 0 rounds"——一个斩钉截铁的错误答案。拆分的目标 crate 调用方一定知道，所以没有默认值，缺参数就退出。
- **`#[tauri::command]` 的参数结构体不要从模块 `mod.rs` 转出**。它们只是宏的反序列化目标，crate 内无人按名引用；转出后 `pub(crate) use` 自身变成未使用导入，clippy 会报出拆分前不存在的新告警。**拆分后的告警数必须回到基线**——基线要用干净 HEAD 导出实测，不要凭印象。
- 可见性撤销表要能区分"结构体本身是 `pub(crate)`、字段却是私有的"这一组合：只撤字段的加宽，不动结构体自己的可见性。沿用结构体的可见性会把 `pub(crate)` 一并还原到字段上，凭空多出三个 token，差异报在字段名上，读起来像字段被改名。

- **拆 CommonJS 服务端文件时，「逐字节可重组」这条证据同样只保证「没丢没重」**，不保证切在条目之间——`server/src/postgres-server.js` 那次，路由分发嵌在请求处理器里（缩进 4 空格），把一个 `if (req.method === ...)` 切两半，拼回去照样逐字节相同。边界守卫因此要额外接受**4 空格缩进的路由头**这一形状：路由分节的第一行不是顶层声明，守卫会误报所有正确的切法。
- **行尾符要跟着分节一起走**。`server/` 全树在 Windows 上是 CRLF（`core.autocrlf=true`），拆分器若先归一化成 LF 再写分节，「拼回原文件逐字节一致」就只在**归一化之后**成立，而这条契约是按磁盘上的字节衡量的（读原始源码文本的断言读的也是磁盘）。比较也要按原样比：归一化后比等于把行尾符这一项从证据里悄悄拿掉。注意 `server/Dockerfile` 本身是 LF（容器里的 sh 需要），**同一目录内行尾符不统一是既有事实，不要顺手「统一」**——`.gitattributes` 只钉了 `*.sh`。
- **「拼起来的模块」不能靠惰性求值来省事**。`auth-security.test.js` mock 掉依赖的导出后**删缓存重新 require** 被测模块，`postgres-integration.test.js` 在 require 之前替换 `pg.Pool`——两者都依赖那些 `require` 发生在被测模块**首次**求值期间。改成按需加载会让它们静默拿到真依赖，测试照样「通过」。
- **语法检查通过不等于生成对了**。装配器把导出表写成裸标识符 `buildConfig,`（应为字符串），`new vm.Script(...)` 解析**完全通过**，错误要等到 `require` 时才炸成 `ReferenceError: buildConfig is not defined`。生成器要校验输出**形状**（表里每项是不是引号包起来的字符串、条数与来源是否一致），不能只校验能否解析。
- **把同作用域的代码切成分节，就别再把分节改成真模块**。它们互相按裸名引用，改成模块意味着手写 import 表——那份表是会与拆分漂移的新代码，而「顺序写在一个入口里、不要惰性」是零新依赖的方案。用 `vm.runInThisContext` 包一个 `(function (__dirname, __filename, module, exports, require) { ... })` 再逐参数调用：前者让 `__dirname` 仍指向原目录（`path.join(__dirname, ...)` 与每个 `./` 相对 require 都靠它），后者让模块尾部的 `require.main === module` 仍然成立——那正是 `npm start` 能拉起服务的前提。代价是**没有逐分节的栈帧**，用虚拟文件名兜底。
- **正向测试通过不等于夹具接到了新的文件**。改完读取路径后要把分节改坏一次，确认测试真的会红：把备份分节里的摘要算法从 hex 改成 base64，对应断言立刻失败，才说明那些断言读的是分节而不是残留的旧路径。
- **控制组要断言「是哪一条检查咬住的」**。`split-js.mjs` 的错位 spec 会被**拼接检查**（缺口/重叠/未到 eof）先拒掉，于是「边界守卫」那一组名义上验证边界、实际每次都测的拼接——报错文本不含预期那句就会暴露。头版五组控制全部是同一个原因被拒，等于只测了一条检查。
- **整文件一个 inherent impl 的模块，拆法是先脱壳再重组**。`store/sync.rs` 主体是第 3-990 行一个 `impl Store { ... }`，切分器看见的每一行都在 4 空格缩进里，于是**全部范围都被边界守卫拒掉**（守卫要求新分节首行是顶层项）。脱壳那一步要**逐行校验**而不是只数花括号：壳内每个非空行都得是 4 空格起头，且要跳过字符串/字符/注释，`&'static str` 的 `'` 靠前瞻区分。重组那一步（Rust 允许固有 impl 跨模块）有两条限制：**面包屑和 `use` 行必须留在壳外面**（`mod` 与它所注释的条目之间的文档注释是 E0761），**套壳必须幂等**——第二遍要认得出已有的壳，否则套第二层，嵌套固有 impl 是 E0658，而它只在第二遍之后才出现，跑一遍的控制组永远看不到。
- **拆壳的校验要剥掉壳，不是把壳放进白名单**。壳是每节四个 token（`impl` `Store` `{` `}`）的包装，不是条目；进「允许的改动」表等于承认那四行是代码差异，而该节真实内容里**没有**它们。剥的时候**按行找壳**，别用整文件的 `^impl...\}` 锚定正则：重组那步故意把面包屑和 `use` 放在壳前面，锚在文件头的正则**不匹配**，扰动静默变成空操作，编译照过——控制组报出的「剥壳不破坏编译」含义是**什么都没改**。判别办法是**先探针验扰动是否落地**，再看编译结果。固有 impl 的错误还有个共同点：**从别的文件冒出来**（拆掉一个方法节是 E0599 于调用方；把自由函数塞进 impl 是 E0425 于调用方），都**不指向你改的那一行**。
- **`carry-doc-comments` 必须在套壳之前跑**。带壳的节以 `}` 结尾，之后跑就找不到可搬的 `///`；而 E0761 是**解析**错误，逐节 `cargo check` 看不见，只有组装后的模块才报。
- **控制组的扰动要断言前提**，否则会报出一个含义完全相反的失败。上面那条剥壳的 case 一开始就是这么栽的：正则不匹配 → 没改动 → 编译通过 → case 判「剥壳不破坏编译」并报 FAIL。**没有改动却报出结论，是控制组最坏的失败方向**——它会让人去改一个本来就对的拆分。每个 case 都用 `expectReject(name, perturb(...))` 形式先确认扰动落地，再判编译。
- **自由函数在私有分节里要 `pub(crate)` 再导出**。`purge_target` 从 `impl Store` 外面搬进一个私有分节后，调用方看不到它（E0425）；标 `bare: true` 让套壳跳过（它是自由函数不是方法，塞进 impl 就是另一个函数），并从 `pub(crate) mod` 里 `pub(crate)` 转出。
- **范围数与分节数不一致要报错**。`store/sync.rs` 原本给 `id_by_guid` 单开了一节，12 个范围配 11 个分节。好在切分器自己拒了——**拒绝优于生成一棵名字对、内容错的树**，后者能通过所有只看名字的检查。spec 的键序还必须与 ranges 的位置序一致：配对是按位置做的，差一位就得到名字正确、内容错误的树。
- **并发会话可能在同一分支上提交，清掉你的暂存区**。本次 `store/sync.rs` 拆分验证完、准备提交时，另一个会话在本分支落了 `b1f1351`（AI 额度双窗口），暂存区随之被清空；重新 `git add` 时只按**自己的路径**加，别用 `-A`，否则会把别人的在途改动一起提交。提交前用 `git diff --cached --name-only` 与 `git diff --name-only` 各看一遍。
- **换会话后第一条命令先 `pwd`**。工作目录停在刚删掉的 worktree 里会让 `cd D:/...` 在父 shell 里失败（ENOENT），报错读起来像 git 出问题。
- **边界守卫要同时看两侧，只朝前看会漏**。`validation starts at 192 on a legal item start` 是唯一漏掉的形状：切口本身合法，但**上一分节被截断**（`types` 少收一行，`impl` 的 `}` 落到下一节开头）。判据是**括号深度的变化**，不是末行长相——按末行先后误伤四种正常结尾：`use` 块的 `};`、结构体的 `}`、换行 import 的行尾逗号、属于下一条目的裸 `#[derive(...)]`。控制组要覆盖四种坏切口（函数体内部、跨节的头花括号、折行签名、缩进注释），且断言报的是**哪一条检查**咬住的。
- **自研词法器的 `'a` 判据会把字节字面量当成生命周期**。判「引号后是标识符开头即为生命周期」时，`b'a'..=b'f'` 里的 `b'a'` 也命中，于是那个 `(` 永远不闭合，深度多出 2，整个文件从那里起被判成「分节留下了未闭合条目」——而那一节其实干干净净地收在 `}` 上。判据要同时看**前一个字符**（`b` 前缀说明是字节字面量）并要求生命周期名字在引号前**已结束**。写完拿六条样例验：`&'a str`、`'{'`、`b'a'`、`(b'a'..=b'f')`、字符串里的 `{`、注释里的 `{`，净深度必须分别是 1/0/0/0/0/0。
- **「所有条目都还在」的检查若用列 0 匹配声明，测试套件一个都数不到**。测试在 `#[cfg(test)] mod tests {}` 里整体缩进一层，于是 `want` 少了全部测试助手，随后「重复声明」检查把**任何带测试的拆分**判成失败——它此前只在无测试的文件上跑干净过。模式要允许前导空白。
- **加宽表条目 `["Name"]` 的默认可见性是 `undefined`**，直接插值进声明变成 `undefinedconst MAX_BUTTONS`，该条目随即从计数里消失，报成「改写丢了条目」。默认应是 `pub(super)`。
- **`pub(?:([^)]*)s+)?` 让裸 `pub` 匹配不到后面的关键字**。整个组可选，于是 `pub` 单独匹配、**不带走尾随空格**，接着 `fn` 无从接上，`pub fn send(...)` 返回 `null`。凡是带「`pub` 或 `pub(..)`」二选一的正则，两支都要各自带空格：`pub(?:([^)]*))?\s+`。
- **从树里反推切分区间时，锚点要落在条目的整个前导上**。用 `fn` 那一行定位，得到的是函数开头，不是分节开头——其上的文档注释与 `#[tauri::command]` 属于**下一节**，于是 `account` 的 `login` 边界落在 `pub(crate) async fn` 上，守卫如实报「不是顶层项」，而树本身完全正常（25 个 tauri 命令属性一个不少）。要连带吃掉文档注释**和跨行属性**：`#[derive(Debug, Clone,` 那种只看 `startsWith("#[")` 会只吃掉第一行。测试套件的锚点用 `#[cfg(test)]` 本身，别用第一个测试助手——助手名 `account` 会撞上文件里更早的同名函数。
- **改完守卫要把已提交的拆分全部重跑一遍**。守卫的每次放松都可能让**之前提交**的坏切口蒙混过关，而那正是放松的理由（`// ---- 分节 ----` 横幅在函数体内必被 rustfmt 缩进，所以列 0 的注释只在顶层条目之间）。区间不要手抄：把每个分节的第一个顶层条目（测试用 `#[cfg(test)]`）回定位到原文件即可推导出来，`mod` 那一节恒从第 1 行开始且**不在 spec 的 sections 里**，要显式补上——漏掉它会把整个文件划给第一个真实分节，守卫仍然通过，只是理由错了。
- **自己写的词法器不能是逐行的，除非语言规定字符串不跨行**。Rust 的 `"..."` 可以用行尾反斜杠续行，`r"..."` 天然跨行，块注释也跨行。逐行扫描的版本在第 1 行开引号、第 2 行关引号，于是把第 2 行**字面量自己的** `{{` 当成代码——`batch_triage_prompt` 的提示词正是这样一个续行了七行的字面量。幽灵深度 +2，把一个干净收在 `}` 上的分节判成「留下未闭合条目」，而真实文件一个字都没错。跨行有状态之后（普通/原始字符串与块注释都延续到下一行）同一个 spec 直接通过。
- **字符串开头的判据漏一个前缀，原始字符串就变普通字符串**。只认 `"` 和 `b` 的话，`r##"..."##` 的 `r##"` 会被当作三个普通字符加一个裸 `"`，于是开了一个**普通**字符串，而它内部的 `"##` 看起来正好像一个从未进入过的原始字符串的终结符——后面全部错位。判据要试 `"` / `r` / `b` 三种开头，`r(#*)"` 里的 hash 组数就是闭合时要找的 `"` 加同样多的 `#`。
- **手写词法器要配一组单测，而且必须含正例**。净深度为 0 的样例只能证明它没把代码当成字面量；一旦某天它把所有东西都吞掉（比如状态机卡住不退出），这组样例会**全过**。所以样例里必须有「这个片段真的没闭合」的正例，期望深度 > 0。本次 23 条：跨行续行、`r#"..."#`、hash 组、`b"..."`、`br#"..."#`、生命周期、`'{'`、字节范围、跨行块注释，加 4 条正例。
- **控制组只能对着真实文件写，就会悄悄不再测它本来要测的检查**。`notification_intelligence.rs` 里没有一行能让**反向**检查（上一分节是否留下未闭合条目）单独发力：每个列 0 的条目起点都在深度 0，而深度非 0 的行（函数体内那对 `#[derive]` / `struct`）是缩进的，正向检查先咬住。反向检查只能另造夹具来验。这不是「这个文件运气好」，是**这类检查在该文件上不可达**——不换夹具，控制组就只剩一个恒真的断言。
- **控制组的 mutant 不能破坏其它不变量**，否则被恒开的检查拦下、什么也没证明。把切点从 612 挪到 660 而不同步挪上一节的终点，撞的是连续性检查，不是边界守卫。每条 mutant 只许改**一个**变量：切点位置。
- **控制组也会自己判断错**。造反向检查的夹具时，我先断言「正向检查应当放行、只有反向检查能拦」，实际拿到的是反向检查的正常拦截，于是把正确行为报成了 `WRONG CHECK`。断言要写在**证据**上（「on a legal item start, but the previous section ends mid-item」这句话同时点出两个半边），不要写在我以为的机制上。
- **嵌套在源码里的引号字面量，测试用例要用拼接构造**。写 `src: 'let a = r##"..."##;'` 时引号与 hash 组极易被编辑器或 shell 改写，改写后的用例照样「测」得出一个结论，但结论是关于错字符串的。本次因此连出两次假失败。写完先 `JSON.stringify` 打印一眼再信它。
- **`include_str!` 的路径相对的是「写出它的那个文件」，不是 crate 根，也不是拆分前的文件**。分节下移一层就断，而修它是**一次真实编辑**，不是移动——于是一个号称纯移动的工具里混进了改写。第一版按「下移了几层」算深度，答案是错的：拆分前 `src/attachment.rs` 里的 `../tests/fixtures/x.hex` 指向的是 `crates/solum-core/tests/`，**在 `src/` 之外**；`src/attachment/tests/mod.rs` 只比 `src/` 深 2 层，于是得出 2，写出 `src/tests/...`——不存在。正确做法是**先解析再重新表达**：拿原字面量在拆分前文件所在目录里解析成绝对目标，再从新位置重新表达同一个目标。深度与 `../` 个数根本不是一回事。
- **重写相对路径要「替换」原有的 `../` 串，不能「前缀」上去**。前缀式写法每跑一次就多一层：第一遍修好、第二遍就坏了。工具必须**幂等**——做法是从**原始**副本（`--pristine`）取字面量，而不是从磁盘上当前的文本取；后者每次都以上一次的产物为输入，逐次爬升。
- **按 `readdirSync` 顺序消费一个全局列表会错位**。文件系统返回的顺序与源码顺序无关，于是某个路径被拿**另一个**原始字面量去重算——结果能解析、能编译、指向另一个文件。需要 `--order` 显式给出分节顺序。
- **验证器的「路径回退」要减的是「**增加量**」，不是「结果总数**」**。原路径本来就带 `../`（`../tests/x.hex` → `../../../tests/x.hex`），减掉全量深度会让两侧差**恰好一个原始计数**，看起来像「丢了一个路径」。这里刻意只做**盲减**而不重新解析：验证器手里只有拆分前的文本和分节自己的文本，没有各自的写入目录，算不出目标；而一个靠猜的重新解析会**放行**一个指向错误文件的路径——那正是这个检查存在的意义。
- **一个纯移动的流水线里，每加一个「真的改东西」的步骤就要配一组控制组**。`include_str!` 重写连踩三处：深度算错（路径跑出源码树）、非幂等（每跑一次多一层）、找不到被 rustfmt 折行的字面量。三处都是「静默地给出错误答案」，编译器和测试都不一定当场抓到——第三处尤其，它会打印「无需重写」这种看起来像成功的报告。
- **`grep` 判定日志为二进制时，会打印「Binary file ... matches」而不是匹配行**——于是下游解析器读到 0 条，循环报「已达不动点、编译干净」，而树上明明有 74 个错误。日志里混着 rustc 引用的源码行，其中有 fixture 里的 NUL 相邻字节。`grep -a` 是承重的：这是这套工具产出过的**最危险的一次失败，而且长得和成功一模一样**。凡是「grep 日志 → 解析 → 判定收敛」的链条，`-a` 不能省。
- **可见性放开是**不动点**，不是一趟**。第一轮只看得到某个分节直接够到的名字；放开它们又暴露出下一层（只有被放开的那个函数才调用的助手）。一趟跑完会留下一棵**仍然编译不过**的树，而错误读起来像是「你放开错了」。手动驱动它，就会有人只因为碰巧重跑了一次就把结果提交上去。写 `wire-until-clean.sh` 收敛它，并且**必须显式检测收敛**——否则循环会一路跑到轮数上限，每轮打印同一张表，看上去仍在推进，实际三轮前就停住了。
- **不动点检测要同时看条目表和字段**。字段自带 `pub`，条目表动不了它（表只放开声明）。只比条目表，循环会在字段仍是私有的时候宣布收敛。
- **从编译诊断推导「该放开哪个分节」时，别信诊断里的分节名**。E0603 报的是**够到**这个名字的文件，不是**定义**它的那个——`pub(super)` 必须加在另一个文件里。两个陷阱：① 每个分节开头的 `use super::sibling::*;`（以及 glob 转出）会把所有兄弟的名字都提一遍，所以判据里**不能收 `use`**，否则每个分节都「定义」了它，返回 spec 里排第一的那个；② 查找必须跑在**移动之后**的树上——移动之前文件还是扁平的 `stage.rs`，同样的 glob 问题反过来发作，于是回退到「够到的那个分节」。两个陷阱都给出**自信的错答案**。
- **`pub(crate)` 的东西不能用 `pub use` 转出**（E0364）。spec 的转出表要能逐条带可见性前缀，别默认全 `pub`。
- **「我这一步成功了」和「这棵树能编译」是两件事**，而把它们混为一谈的每一种写法都长得像成功：① `fix-section-imports.mjs` 用 `out.includes(CODE_BRACKET)` 判断「无事可做」就返回成功，而 `cargo --message-format short` 对**解析错误**（E0761）打的是没有方括号码的裸 `error:`，于是三个 E0761 全部漏过，打印「no unresolved names」并 exit 0。② 循环脚本 `node … into the log` 不看退出状态，于是这一步失败了也照常往下走。③ 收敛检测比的是**放宽表**，而某个名字放宽工具归不到任何分节时表确实不再变——循环于是在一棵带 2 个 E0624 的树上宣布「已达不动点」。三处修法是同一个：**判据要用退出码和状态，不用文本里有没有某个子串**；收敛要同时看诊断本身。
- **分节边界不能切开「一个类型 + 它的 trait 实现」**。`struct DataImportTool` 和 `impl Tool for DataImportTool` 分处两个分节时，编译器给的是 E0277「trait bound not satisfied」——**不是**「找不到这个类型」，而错误行指向 `Box::new(DataImportTool)`，读起来像注册表写错了。修法是把边界挪开：类型留在声明它的分节，实现可以走。Rust 允许跨分节实现一个类型，所以这条不是硬性限制，但**一旦允许，分节边界就变成任意的**——那时应该重新想怎么切，而不是让工具去迁就。
- **E0624（私有关联函数）和 E0603 是两件事，但归属查找把前者当成了后者**。方法写在 `impl` 块里，缩进着，`^` 锚点的顶层声明式匹配不到，于是归属查找回退到**够到它的那个分节**——恰好是唯一不可能有用的答案。循环于是看到一张不再变化的表，宣布收敛，而方法仍然是私有的。两个修法：E0624 走 `methods` 表（按缩进锚定），以及归属查找把 `impl Trait for X` 行也当作 X 的声明——分节里每个私有 `impl X { fn … }` 都会命中这条。
- **跨分节的 `///` 文档注释**：切点落在注释和它所注释的条目之间时，注释留在文件末尾什么也没注释（E0761）。这是**解析错误**，所以单独 `cargo check` 一个分节看不到，要整个模块拼起来才出现。工具 `carry-doc-comments.mjs` 把它带进下一个分节，顺序必须取自 spec 的 `ranges`——用 `readdirSync` 的话注释会落到**另一个**分节上，而那同样编译通过、同样没人发现。附带两条：① 切分器会给每节补一个换行，所以「最后一行是注释」在测试里必须按**最后一个非空行**判断，看 `split(-1)` 会看到空串，然后结论变成「没什么可带的」而前提悄悄变假；② 带过去之后注释和条目之间多出的空行会让 `cargo fmt --check` 失败，而错误指向那个条目，不指向空行。
- **控制组的前提必须自己检查**。这次有两条控制组在自己身上栽了：① 扰动只改了临时副本，而被测工具**按路径**读仓库里的文件，于是它根本没看见扰动、两条用例都报「通过」；② 「新切分树少了文档行」这个前提写成了「仓库里的树少了文档行」——而仓库里的树**已经带过了**，两者计数相等，控制组于是要么恒真要么恒假。**对一件事的控制要能区分「工具做对了」和「前提不成立」**，所以每条用例都要先断言前提（原文有 N 行、新树确实有 M 个分节以注释结尾），前提不成立时要**报出来**而不是让断言安静地通过。
- **`wire-until-clean.sh` 自己造的失败会伪装成被测物的失败**：它把 spec 的 `ranges` 原样传下去，丢掉 `:slug` 后缀，而切分器要求 `range:slug`——于是每轮都「split failed」并退出，看起来像切分器坏了。派生的量（`ranges`、`--order`）和它们**对应的名字**必须成对从 spec 出，且长度不一致时**拒绝**而不是错位：错位一对 `range:slug` 会得到一棵分节名正确、里面代码错误的树，通过所有只看名字的检查。
- **`pub(crate)` 的转出、以及无人使用的转出**：E0364 只在转出比被转出项宽时报（已记）；反过来，**转出比需求宽**是 clippy 的 unused import。这次 `kind_label` 被转出，但 `review.rs` 有自己的私有同名函数，于是根本没人够到它。转出表应当只列真正被外部到达的名字——按「拆分前这个分节文件里被别的文件引用过」来列，不是按「拆分后 mod.rs 看起来完整」。
- **按错误码分派时要覆盖每一类，漏掉的一类会伪装成「已经收敛」**。`wire-until-clean.sh` 的导入步骤失败时只数 `E0603`/`E0624` 两种错误，数到 0 就当「这一步能做的做完了」并继续。`E0616`（字段私有）**不属于那两种**，而它恰恰是下一步 `widen-fields.mjs` 的活——于是树带着 7 个 E0616 走进了放宽步骤，那一步看不到自己该处理的错误，循环在**「没有可放宽的私有项」**这句话上退出，而那 7 个字段仍然是私有的。每一类错误都要写清它归谁：E0603/E0624 归放宽轮次，E0616 归字段放宽，其余才是这一步自己的问题、才该放弃。判据要落在**循环结束时树干不干净**，而不是**这一步该做的做完了没有**。
- **一次没有真的扰动的控制组，对被测物一无所知**——它测的是「我写对了锚点」。这次三条都栽在这里，而且失败的样子和「验证器有 bug」一模一样（都是「通过」）：① 锚点写成 `MAX_HEADER_BYTES`，它只出现在 `format` 节里，目标 `limits.plaintext as u64` 又已被 rustfmt 折行，sed 一处都没替换，文件逐字节没变；② 测 include 路径时用了 `payload.json`，而它**正是**拆分重新落到 `../../../` 的那一个——`PATH_GAIN` 的回退会把它改回去，两边仍然相等。**回退按设计会撤销它自己做的改动**，所以要测「路径错了」必须去动回退不管的那部分（这里是文件名）；③ 测「条目重排」用了一个**只有一条条目**的分节，「移到末尾」等于原地不动。**每条用例先断言自己的前提**：锚点在不在、替换后文件是否真的变了、这一节是否有两条以上条目；前提不成立要**报出来**。
- **可见性放宽的两层是独立的，`WIDENED` 里要分开记**：一个类型可能因为某个兄弟分节要**提到**它而放宽，同时它的字段因为另一个分节要**读**而单独放宽。`DecodeLimits:fields+` 里 `fields` 表示「只动字段」，`+` 表示这个类型自己原本的 `pub(super)` 也是拆分加的。写错的方向是安静的：只写 `fields` 会让类型自己的 `pub(super)` 留在原地，比较报出一个 token 的差，看起来像丢了个关键字，而不是允许表少写了一半。
- **`macro_rules!` 不是路径：它是这次拆分的第三类跨分节引用**（前两类是条目 E0603/E0624、字段 E0616）。父模块里的宏用 `use super::*;` 到不了任何分节，`use super::parent::name` 也不存在——**它没有命名空间可以被具名**。而 `mod` 块是锚在**第一条 `use`** 上生成的，原始文件里位于导入之后的 `macro_rules!` 于是落在所有 `mod` **下面**。2018 版起父模块的宏对子模块**按词法可见**（`macro_rules!` 有词法作用域），所以修法是**把它挪到 `mod` 块上面**，**不是加 `#[macro_use]`**——后者只是 2015 版的遗留路径，加了也不影响结果。
  这个失败的样子特别坏：**属性加上了、每一步都报成功、`cargo check` 仍然说找不到宏**。「属性在」和「宏可达」同时成立，所以查「有没有加属性」的检查全部通过。**判据要落在编译上**，新增的控制组断言的正是「把宏挪回 `mod` 下面之后必须编不过」。
- **正则里用「路径字符类」而不是懒惰前缀**：同一个文件里三条同形的诊断正则，`UNRESOLVED`/`PRIV_METHOD` 用 `^(.*?[\\/][a-z_]+[\\/]mod\.rs:…)`，新的 `WANT_MACRO` 我写成了 `^([a-zA-Z_:0-9]+[\\/][a-z_]+[\\/]mod\.rs:…)`——**crate 目录叫 `solum-core`，连字符两类都不匹配**，于是在一条就躺在日志里的诊断上得到 0 命中，然后把这个错误报成「不是我能处理的类别」，而它恰恰是。**要匹配路径就给一个能匹配分隔符以外的任何字符的前缀**，别去枚举路径里可能出现的字符。
- **`node -e` 会吃掉正则里的反斜杠**，`[\\/]` 到达时已经变成 `[\/]`，只匹配 `/`。于是探针打印的 `src` 和文件里写的**不是同一行**，而探针是在验证「这个模式对不对」——它验证的是自己的抄写。**探针要从文件里把工具真正用的那条正则读出来**再测，别在命令行里重新敲一遍。
- **被带过去的 `///` 会和下一节原有的注释合成一段**，去空行的前瞻若只认「下一行是条目开头」就会漏掉，`empty_line_after_doc_comments` 于是报在一个**单看完全正常**的 `///` 行上。前瞻要接受「下一行还是 `///`」。
- **拆分前 `pub`、拆分后没人够得到的类型会开始报 dead_code**，而 `#[allow]` 是错的答案：`NullReasoner` 拆分前是 `pub`，进到私有模块后没人构造它——它本来就是公开可达的，诚实的修法是把它也转出。转出表按「拆分后确有外部文件到达」列，不是按「拆分前是 pub」。
- **控制组要断言实测出来的机制，不是设想的那个**：这条控制组一开始断言「用到宏的分节带 `#[macro_use]`」，而那棵树里根本没有这个属性、却编译通过——工具发现不需要它。断言一个**没有发生的事实**，得到的结论和断言错了方向时一样没有意义。
- **`--message-format short` 打的是消息文本，不是 lint 名**。断言 clippy 有没有报某条 lint，要找的是「消息 + 它指名的文件」两样都有；只查 lint 名是在测 cargo 的输出格式。而且这类断言要 **`utimesSync` 一下**：cargo 按 mtime 判指纹，**把相同的字节写回去不算改动**，于是「扰动 → 观察」这一步看的是一个没重编的 crate，观察不到任何东西。
- **范围区间的边界数字是左边那一节的最后一行**（切分器内部是 0 基半开区间，守卫是 `parts[i].from !== parts[i-1].to`，所以 `1-32`/`32-88` = 1..32 与 33..88）。差一行的后果不是少一个字符，而是**少一个 `}`**——编译器报 `unclosed delimiter`，而**这个诊断落在下一节的行号上**，没有任何东西指向真正写错的边界。切点要落在条目之间：`platform_matrix` 的 `}` 在 194 行，切点取 194 会截断函数，取 196 会把下一个结构的 `#[derive]` 划给上一节。**推导出的量和它们对应的名字要成对**（已记），这里补一条：**边界语义要靠测量确定，不要靠读代码猜**——三种读法都能自洽。
- **控制组把规则写反，比没有控制组更糟**。`negative-control-ranges.mjs` 第一版把边界语义写反，于是「区间之间有空隙」全部失败、**未扰动的范围表被报成坏的**，读者会去改 spec 里本来正确的 ranges。**每条「未扰动必须通过」的断言是一条前提**；前提不成立时要报出来，而不是让一堆假失败看起来像真发现。
- **手写的深度计数会把 `&'static str` 的 `'` 当成字符字面量的开始**，于是一节再也没闭合，**两个编译得好好的分节被判为不平衡**——这个方向最坏，它让人去修一个已经对的边界。Rust 自己的词法器用前瞻区分：`'` 后面紧跟 `\` 或 `'`，且再后面不是标识符字符，才算字面量。字符串/字符/两种注释都要处理：这个仓里满是中文界面文案，里面的 `{` 会被当成未闭合的块。
- **「本节最后一行」要在过滤空行和注释之后再取**。以空行收尾的分节（每个文档注释前的边界都是）会报出**下一节**的第一行，然后去比对一个不属于它的字符串。
- **带 `#[derive]` / `#[serde]` 的结构，边界必须取在「下一条目的文档注释或第一个属性之前那一行」**，也就是左边那节拥有的最后一行。这个文件 12 个分节里有 12 处这样的结构，差一行的症状是**下一节丢了属性**（不是少一个 `}`），而诊断报 unclosed delimiter、行号落在**另一个分节**里。**推导边界要从条目清单来，不要从「这个结构从哪一行开始」倒推**——属性行是结构的一部分，倒推会把属性划给上一节。
  可靠的做法：先打印出每个顶层条目的**起始行**（列 0 的文档注释、属性、关键字），再取「下一条起始行减一」当边界。逐个打印那 12 行确认全是空行，比事后看编译错误快得多——错误指向的是**受害的分节**，不是写错边界的那个。
## 数据与同步

- Core 时间必须注入；测试读取系统时钟会造成不可复现的提醒/合并错误。
- SQLite schema、同步表白名单、触发器、apply 分支和固定夹具必须一起演进；少一处会形成静默 history gap。
- JSON 解析失败是错误，不等于“未知表隔离”；隔离只处理被明确识别为可泊车的未来数据。
- 状态文件和导入使用临时文件 + flush + rename；恢复只写入经过完整预检的空目标。
- `local_only` 是数据分类，不是 UI 标签；任何 recall/LLM 路径都必须在数据层过滤。
- 纯移动式拆分的等价性证据要**按分节**给，不是整文件比一次：整文件 diff 会被 rustfmt 对变长签名的换行淹没，看起来像有实质差异。逐分节比 token 流（标识符/字符串/字符/裸串 + 逐字符标点），并显式列出“允许的改动”（可见性放开、rustfmt 补的行尾逗号），剩下的必须完全一致。
- 找“分节起点”不能只搜 `// ---- `：末尾的 `#[cfg(test)]` 块常常没有横幅，按“首个横幅”切片会**整段丢掉测试套件**而脚本仍报成功。行范围要显式声明。
- **“按字节拼回原文件完全一致”证明不了边界切对了**。切进条目中间（比如把 `fn validate_bootstrap` 的签名留在上一节、函数体放进下一节）后，各分片照样首尾相接、拼回逐字节相同。这条证据只保证"没丢没重"，不保证"切在条目之间"——`portable_generation` 那次就是这么把签名切掉的，直到后面的接线步骤报"找不到该声明"才暴露，而且只是碰巧。`split-into-module.mjs` 因此加了边界守卫，**断言新分节的首行是不是顶层项**（`#[]`、文档注释，或列 0 的 `pub`/`const`/`fn`/`struct`/`enum`/`impl`/`mod`/`use`/`type`），而不是旧分节的末行：被切断的条目尾部往往正好是一个列 0 的 `}` 或 `;`，和干净结尾无法区分，后面再跟一个空行时"回退跳过空行"还会停在切口上而非真正的断点。守卫要**报出切口两侧的行号与内容**，"哪里不对"必须能直接定位到该把边界挪到哪一行。反向验证三种形状：缺口、重叠、起始落在条目内部都要被拒；紧贴列 0 `}` 之后的合法边界要放行（第一版守卫要求边界前必须有空行，把这种合法切法也拒了）。
- 拆分后手写跨分节 `use` 极易双向出错：**`use super::*;` 已经把父模块 re-export 的名字带进来了**，再 import 一遍就是 E0252（`defined multiple times`）；漏掉则是 E0425/E0422（`cannot find ... in this scope`）。而"哪个名字归哪一节"靠人抄扫描结果必然出错。正确做法是**由编译器驱动**：读 `cargo check` 的未解析名字，按各分节的声明反查归属，补 `use super::<分节>::...` 后循环到干净；父模块已可见的名字（常量 + `pub use` + 父模块自己的 `use`）自动跳过。
- 私有字段放开的诊断**随工具链变**：旧工具链报 E0616（`field \`f\` of struct \`S\` is private`），新工具链报 E0451 复数形式（`fields \`a\`, \`b\` and \`c\` of struct \`S\` are private`）。复数形式的字段列表带"and"，**单个 `` `[^`]*` `` 跨不过去**，必须 `[^`]+` 配一个惰性 `.*?` 找到 `of struct`。只写 E0616 的脚本遇到 E0451 会打印"没有 E0616 字段隐私错误"然后退出——**读起来像"没什么可放开的"，实则是正则写错了**，这是最危险的错误方向：正则要对着真实诊断逐段二分确认，别照着想象写。同理，字段查找若用平铺 `readdirSync`，分节落成 `*/mod.rs` 后一个文件都扫不到，同样静默失败；改为递归。
- 正则里 `///` 这类以斜杠开头的模式**不能塞进交替组**：`/^(#\[|///)/` 是未闭合的分组（`///` 里的 `/` 提前结束了字面量）。文档注释与属性这类"前缀相同但长度不同"的模式要拆成独立正则。
- 改写脚本里用 `find`/`replace` 逐条替换**极易把两行合成一行**（`x = a.replace(r, (head) => \`${vis} ${head...}\`)` 再叠一次同样形式的 replace），中间过程还会被 shell 的 `node -e` 吃掉反斜杠和括号。**写 `.mjs` 文件执行**；替换后**立刻按行号回读**。
- 自研脚本里 `eval` 一行 `/.../flags` 文本不是表达式（SyntaxError），要 `new RegExp(src, flags)` 构造；`String.prototype.matchAll` 要求带 `g`，漏了会抛 `called with a non-global RegExp`。
- 手写的 Rust 花括号计数器会漏判**字符字面量与生命周期的分界**。`&'static str {` 里 `'s` 后面跟的是字母，旧判据（要求引号后第二个字符非标识符字符）把整段当成字符字面量一路扫到行尾，**顺带吞掉行尾的 `{`**。结果是文件末尾深度算成 -1、其后所有顶层边界整体错位，而脚本只打印一行 WARNING 就继续。判据应只看引号后**第一个**字符：`'` + 标识符开头 = 生命周期。`#[error("... {0}")]` 这类 format 占位同样会干扰朴素计数，字符串必须先剔除。**任何自研词法器，发现深度不为 0 时要当错误处理并逐行定位，不能只警告。**
- 等价性脚本”还原可见性”时要还原**到拆分前的实际值**，不能一律删掉 `pub(...)`。测试夹具常是拆分前就写好的 `pub(crate)`（在单模块里用不到那么宽），拆到兄弟模块后降为 `pub(super)`；脚本只删不加就会把拆分前就有的 `pub(crate)` 一并抹掉，报出假的差异。让脚本按 `名字:拆分前可见性` 显式声明。还原要覆盖三种形状：项本身、元组结构体字段 `struct S(pub(super) T)`、具名字段 `struct S { pub(super) f: T }`——只做前两种会漏掉后面几种。**注意 RegExp 里 `pub(?:super|crate)` 是分组不是字面量**（要写成 `pub\\((?:super|crate)\\)`），写错的表现是”还原从未触发”，不是报错。
- 等价性脚本本身要做**反向验证**：造一个含多余语句、含改动过的函数名的副本当对照，确认脚本报错。写完脚本先证明它会咬人，再拿它判真伪。反过来，故意只删一行 `use` 时脚本不报——那是设计上允许的差异，不该算失配。半路发现对照没生效时，先确认变异是否真的落地，再怀疑脚本。
- `mod.rs` 那一段不能靠 token 比对下结论：条目都搬进了分节，模块文件只剩文档头和归位过来的 `use`，逐 token 比对是空转（还会报"零 token"）。改为断言原文件的 `use` 一条不缺且相对顺序不变——兄弟分节靠 `use super::*;` 看到它们，丢一条会静默改变每个分节的可见名字。顺序本身不必强求：`rustfmt` 会把 `use` 块重排成自己的规范序（std → 外部 crate → `crate::`），报告"顺序被重排"即可，缺失才要报错。**有几项 import 是有意下放到唯一使用它的分节的**（典型是 derive 宏），这类要显式声明，否则"缺失"会淹没真缺失。
- **不要静态预测哪些结构体字段需要放开**。私有字段名会出现在别的分节的字符串、注释、文档和无关结构体里，文本扫描不是过度放开（改了模块对外表面）就是漏放。正确做法是读 `cargo check` 的 E0616 诊断、只放开编译器点名的结构体，循环到干净为止。同理"哪些私有项被别的分节引用"要用词边界匹配，但**在 shell 单引号里写 `node -e` 时 `\\b` 会塌成 `\b`（正则字面量里是退格符）**，静默匹配不到任何东西、读起来像"没有跨分节引用"——正是最危险的错误方向。写成 `.mjs` 文件执行，别内联。

## Android/设备

- “权限已授予”不等于后台能力工作；receiver/service 必须出现在 Release manifest，并验证锁屏、进程回收与重启。
- `force-stop` 会让 Android 主动阻断 alarm/receiver，不能用于正常后台恢复验收。
- 浏览器健康接口成功不证明应用 rustls 可达；按 DNS、SNI、ClientHello、代理和设备网络逐层探测。
- `offsetParent === null` 对 fixed/sticky 元素不代表不可见；用 computed style、视口矩形和必要的截图判断。
- DOM 属性/类名正确不等于渲染正确；mock-IPC 后仍需真实浏览器/设备走查。
- WebView 瞬态界面必须统一登记到同一个栈顶 history 条目；漏掉一种弹窗/面板会让 Android 返回键在浮层仍可见时误切底层视图。程序关闭浮层后的异步 `popstate` 也要吞掉，不能再触发一次视图回退。
- 响应式覆盖必须声明在对应桌面基础规则之后；账号门曾因桌面双列规则后声明，在 390px 下把说明栏压成单字竖排并覆盖表单。真实 320/390/1000px 渲染是发布门槛，不能只看选择器存在。
- 不要在启动或一次对话写入后刷新所有隐藏页面；台账单次刷新会并发读取多个数据层。隐藏视图进入时再刷新，高频刷新要 single-flight，页面隐藏时暂停周期任务。
- 渲染函数内向 `document` 注册监听器必须可解绑；组件详情菜单曾在每次进入时累积外部点击监听，造成越用越慢和重复回调。
- `account_status_get.logged_in=true` 不代表会话仍可用；刷新 token 失败会写入 `state_error`。只渲染错误文案会把用户困在伪登录态，必须与普通 IPC 的 401/过期错误一起进入统一退出与登录重定向。
- 不把相册原图直接塞进 `localStorage`：高像素照片会迅速撞上 WebView 配额并放大解码内存。先限制输入体积、居中裁切、压缩并再次检查编码后大小；解码失败或超限时保留原头像。

## 服务端

- Schema 开头 `revoke all on schema public from public` 会连 pgcrypto 的 `digest()` 一起锁死，运行时角色解析不到扩展函数并报 `function ... does not exist`；库内哈希用 pg_catalog 内置 `sha256()`，不要依赖 public schema 的扩展函数。
- 窗口函数先于 `LIMIT` 执行：把 `octet_length(ciphertext)` 累计窗口和密文选择写进同一层查询，`since` 之后的整段历史都会被解包。pull 必须先在有界候选集上算尺寸，再对入选行取密文。
- 集成测试不自行初始化角色/schema，需按 compose migrate 同款流程预置全新测试库；断言含全局 identity 序列号（如 42/74），复用跑过的库会假失败。
- 无本地 Postgres/Docker 时，可在 VPS 起 `--rm` Postgres 容器（仅绑 127.0.0.1）+ SSH 隧道跑集成测试，用后即删。
- **服务端 LLM Upstream 容器网络与 CPA Guard 连通**：
  - 客户端不直连供应商或 CPA，而是经由 Solum Center（`solum-cloud` 容器）代理；
  - 客户端更新默认模型（如从 `qwen3.5-2b` 迁移到 `gemini-3.8-flash-high`）时，**必须同步检查并更新 VPS 生产环境的 `.env` 配置**（`SOLUM_DEFAULT_MODEL`、`SOLUM_ALLOWED_MODELS`、`SOLUM_LLM_BASE_URL`、`SOLUM_LLM_API_KEY`）并重启容器，否则客户端登录后请求 Center 会直接报 502 upstream unavailable 或模型不在目录；
  - 容器不能通过自身回环访问宿主服务；核对实际 Docker 网络、网关可达的监听地址和防火墙。不要把历史网桥 IP 或 `0.0.0.0` 当作所有部署的固定要求。

## 安全

- Guard token 一次性且绑定动作/参数/主体；模型或页面不能自行构造。
- 不把生产 token、通知正文、健康数据、设备账号或签名材料写入日志/文档/测试夹具。
- 主机 API、模拟器、Debug 和真机 Release 结论各自独立，报告必须写清证据层级。
- 登录成功即重启应用（Android 重启 Activity、桌面重启进程），登录命令的返回值到不了任何 UI；必须跨重启呈现的一次性内容（如首登签发的恢复码）要先原子落盘到账号 profile 目录，由下次启动读取并强提醒、确认后才删除。签发信封成功但展示链路中断，等于把 E2EE 唯一钥匙静默丢弃，且设置页状态会给出「已设置」的假安心。
